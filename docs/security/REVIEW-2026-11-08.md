# Security review — 2026-11-08 (Hermes, three parallel reviewers)

Scope: contracts (vendor-registry, treasury, test-token), web server side (API routes, gasless relay, uploads,
hosting), agent (readers, checks, 1Click validation, pay flow, keys, notifier). Read-only review with throwaway
proof-of-concept tests outside the repo. The official Claude Security plugin scan is still to run (Claude Code
login/usage limits); it will be added as a second opinion.

## Summary by severity
| ID | Sev | Area | Finding | Status |
|---|---|---|---|---|
| C-H1 | High | treasury | Stolen agent key can auto-pay cross-chain proposals to any `deposit_address` (incl. attacker's), up to caps | Confirmed (test) |
| W-H1 | High | relay | Relay accepts delegates signed by keys not on the sender account / nonexistent senders → relayer NEAR drain; replay | Confirmed (PoC) |
| W-H2 | High | upload | Public, unauthenticated uploads in execute mode → burn NEAR AI credits + agent key allowance, spam proposals/alerts, lock caps | Confirmed |
| A-H1 | High | agent | Invoice alone picks which registered vendor is paid; vendor name never checked against registry display_name | Confirmed (probe) |
| C-M1 | Med | treasury | Fixed 30-day buckets let the monthly cap be spent twice within seconds at the boundary | Confirmed (test) |
| C-M2 | Med | treasury | Agent-paid-for storage (big flags) drains treasury NEAR; low balance can strand callbacks in Executing | Confirmed (size) |
| C-M3 | Med | registry | Free entries (contract pays storage) let anyone exhaust registry NEAR; deleted accounts leave entries | Confirmed (code) |
| W-M1 | Med | upload | Body buffered before size check; files kept forever; huge PDF pages → OOM | Confirmed (code) |
| W-M2 | Med | hosting | Agent child process gets every secret (env spread); container runs as root | Confirmed |
| A-M1 | Med | agent | Duplicate check evaded by invoice-number formatting / amount ±0.01 | Confirmed |
| A-M2 | Med | agent | Credit notes (−, parentheses, CR) parsed as positive payable amounts | Confirmed |
| A-M3 | Med | agent | Injection can blank payment text/line items to suppress warning holds; address regex gaps | Confirmed regex gaps |
| A-M4 | Med | design | Forged invoice burns the hash so the genuine one is later rejected as duplicate | Suspected |
| C-L1..L6, W-L*, A-L* | Low/Info | various | Executing not recoverable; u32 id aliasing; hashes burned on reject/fail; version reset on re-add; pause not re-checked in callbacks; missing security headers; raw errors; public app pages; npm audit advisories; 1Click slippage/minAmountOut/deadline not checked; headline classification from attacker text; ambiguous European amounts; silent E2EE fallback | Mixed |

Key point: no path lets an outsider redirect money to an address the vendor didn't register. The serious issues are
(1) what a stolen agent key can do on cross-chain payouts, (2) abuse of the public demo (relay + uploads), and
(3) paying the wrong registered vendor / double-billing via crafted invoices.
